### T8 real 3D grass (GrassBuffer) M1: terrain-driven distribution, in-game verified
- New device-layer class `W3DGrassBuffer` (`Core/GameEngineDevice/.../GameClient/W3DGrassBuffer.{h,cpp}`), hooked into the particle/weather pass (after `W3DSnow`). Scatters crossed alpha-test quads **only on cells whose terrain class is grassy**, merged into one static index buffer => a single draw call per frame. Placement window is camera-centered and rebuilt only when the camera travels past `GRASS_REBUILD_DIST` (never per frame). Pure render-side, zero logic/CRC impact.
- Terrain gate relaxed from `TERRAIN_GRASS`-only to a grass **family** (`isGrassyTerrainClass`: GRASS / ACCENT_GRASS / COBBLESTONE_GRASS / FIELD) — ZH green tiles report e.g. `GrassMediumType8 class=27`, which the strict check missed (grassHits was 0). Building keep-out: iterate `KINDOF_STRUCTURE` objects, take footprint radius (`max(major,minor)` for BOX) + margin, drop candidate cells inside — stops grass poking through buildings.
- Menu/shell gate: `isInGame() && !isInShellGame()` so the flying main-menu background camera no longer forces a full rebuild every frame.
- Two hard-won transform/placement bugs (both made grass invisible or misplaced, NOT a distribution problem):
  1. The weather pass leaves `D3DTS_VIEW` at **identity** (W3DSnow sets it and never restores). Adopted the W3DSnow convention: transform each world corner to **view space on the CPU** (`Matrix3D::Transform_Vector`), submit with `VIEW=identity`, and leave `PROJECTION` untouched (scene projection already bound). Feeding world verts + a manually-set VIEW/PROJ double-transforms under DXVK.
  2. **Window center must be the look-at pivot `TheTacticalView->getPosition()` (ground center of view), NOT `get3DCameraPosition()` (the eye)**. On a tilted RTS camera the eye sits up and *behind* the pivot, so centering on it scattered the whole field behind the camera — symptom: grass invisible by default, appearing only after a 180-degree camera turn. Saved as a durable pitfall memory.
- Memory-wall hardening (32-bit address space): `DX8IndexBufferClass`/`DynamicVBAccessClass` `WriteLock` can return **null** under low memory (esp. on load-game device-reset re-acquire); added null guards that degrade grass to off instead of writing through null. Root fix for the texture-loss/pressure side is the in-progress 64-bit build.
- Naturalism pass (user confirmed "good enough"): density 35->20, colors de-saturated to olive (`0xFF4E6B32` tip), smaller clumps, wider per-clump tint variance, and a **circular window with a soft hash-driven rim fade** replacing the square hard border (was reading as a rectangular lawn patch).

### Shadow system S1+S2: breathable shadows and a resolution tier (renderer modernization)
- Implemented S1 (density + slight cold tint across **all three** shadow paths) and S2 (shadow-map resolution as a per-user option) from `渲染器现代化调研/阴影系统升级方案.md`. Configuration channel is `OptionPreferences` (`Options.ini`), deliberately **not** `GlobalData`: `Data\INI\GameData` is folded into `m_iniCRC` by `GameEngine.cpp` `xferCRC`, so editing packaged INI would break old replays and room CRC checks (same reasoning as the earlier Bloom feature). No new GlobalData field, no INI repack, no determinism impact.
- Source verification overturned three claims in the plan document before any code was written: (1) `W3DShadow.h` has **no** `setOpacity(Int)` — only `setShadowColor/getShadowColor` (`setOpacity` belongs to `TerrainDecal`/`RadiusCursor`); (2) `m_shadowColor = 0x7fa0a0a0` is consumed **only** by the volumetric fullscreen quad (`W3DVolumetricShadow.cpp` with `SRCBLEND_DESTCOLOR`), it appears in the projected path solely inside commented-out code, so it was never the "global black" cause; (3) `SHADOW_PROJECTION` does project onto other `robj`s (AABB-overlap material-pass push), not only terrain.
- Real S1 injection points found and wired: `W3DProjectedShadow::init()` `Set_Intensity(0.4f,true)` (the actual projected density knob), `TexProjectClass::Pre_Render_Update`'s multiplicative branch `Set_Emissive(1-i,1-i,1-i)` (where intensity becomes gray emissive), and `W3DProjectedShadow::m_diffuse` (permanently `0xffffffff`, the decal vertex color).
- New shared engine hook `TexProjectClass::Set_Projection_Color(r,g,b)` (`Core/Libraries/Source/WWVegas/WW3D2/texproject.{h,cpp}`), defaulting to 1,1,1 so behavior is bit-identical when unused. Safety argument for tinting: the shadow map is cleared white with ambient 0 (black = occluded) and the shader is `GRADIENT_ADD`, so `src = clamp(texel + (1-i)·c)` leaves unshadowed pixels at identity 1 — only genuinely covered pixels get the colored darkening, and blurring that map in S3 will yield a natural penumbra for free. `TexProjectClass` has exactly one consumer in the workspace (projected shadows), so the extension carries no blast radius.
- Options keys (defaults are the new look; `40 / 37 / 1000 1000 1000` restores the original): `ShadowProjectedIntensity`=35, `ShadowVolumetricIntensity`=30, `ShadowTint`="940 1000 1060" (permille, reused for decals), `ShadowMapResolution`=768 (512/768/1024/2048). `W3DShadowManager`'s constructor reads them once and caches, computes the volumetric ARGB multiplier (defaults land on `0x7fa8b3bd` vs the original `0x7fa0a0a0`) and logs `[SHADOWS] proj=… vol=… tint=…/…/… rt=…` to `stderr` because `DEBUG_LOG` is compiled out in release.
- S2 implementation: the two `DEFAULT_RENDER_TARGET_*` macros became a fallback baseline; `W3DProjectedShadowManager` now stores `m_renderTargetSize`, `ReAcquireResources()` requests the configured size and degrades A8R8G8B8 → no-alpha → halve (1024→768→512) until a target is created, and the `SurfaceClass::Copy` in `updateTexture()` was switched from the macros to the texture's actual `Get_Width()/Get_Height()` — without that a non-768 tier would copy a partial shadow. `W3DShadowTexture::init` inherits dimensions from the render target's `Level_Description`, so it follows automatically.
- **VRAM correction**: shadow maps are allocated **per distinct projectable model** (deduplicated by model name in `W3DShadowTextureManager`, shared between instances, freed only on map reset). A8R8G8B8 costs ~2.25 MB/tex at 768² and ~4 MB/tex at 1024², and a typical skirmish map has 30-60 projectable models → ~70-135 MB at 768 versus ~120-240 MB at 1024. The document's "about 4 MB total" was off by an order of magnitude, so the default stays 768 and 1024 is a measured tier for the user's 780M iGPU + 4K box.
